# UKNC_CODES.md — справочник кодов УКНЦ и MACRO-11

Источник истины — код рантайма (`CodeGen_RuntimeCpu.cs`, `CodeGen.cs`) и
проверка на эмуляторе. Всё, что ниже, сверено с ними.

## ⚠️ КРИТИЧНО: восьмеричное vs десятичное

Это источник большинства багов в проекте. В MACRO-11:

| Запись      | Что это                    | Значение (дес) |
|-------------|----------------------------|----------------|
| `#33`       | восьмеричное (по умолчанию)| 27             |
| `#33.`      | десятичное (точка в конце) | 33             |
| `.BYTE 33`  | восьмеричное               | 27             |
| `.BYTE 33.` | десятичное                 | 33             |

**ПРАВИЛО:** в MACRO-11 число БЕЗ точки — восьмеричное, С точкой — десятичное.

**ПРОВЕРКА перед записью любого управляющего кода:**
1. Я хочу код N (в десятичном из таблицы ASCII)?
2. Если пишу `#N.` (с точкой) — N должно быть десятичным.
3. Если пишу `#N` (без точки) — N должно быть восьмеричным.
4. Перепутал → код уедет. ESC(27) написанный как `#33.` даст '!' (33).

## Управляющие коды (ASCII)

| Символ | Дес | Окт  | В MACRO-11 (дес) | В MACRO-11 (окт) | Назначение            |
|--------|-----|------|------------------|------------------|-----------------------|
| ESC    | 27  | 33   | `#27.`           | `#33`            | начало escape-послед. |
| CR     | 13  | 15   | `#13.`           | `#15`            | возврат каретки       |
| LF     | 10  | 12   | `#10.`           | `#12`            | перевод строки        |
| FF     | 12  | 14   | `#12.`           | `#14`            | очистка экрана+home   |
| BS     | 8   | 10   | `#8.`            | `#10`            | курсор влево          |
| TAB    | 9   | 11   | `#9.`            | `#11`            | табуляция             |

## УКНЦ escape-последовательности (консоль, порт @#177566)

ESC = 27 (дес). Параметры передаются ASCII-цифрами (значение + 48).

### Позиционирование курсора (gotoxy) — VT52-стиль
```
ESC 'Y' <row+32> <col+32>
27, 89, y+32, x+32
```
**ВАЖНО: сначала ROW (y), потом COL (x)** — так требует VT52 и так делает
`RTGOTO`. Раньше в этом файле было написано наоборот; это была ошибка.

Со стороны Mini-C порядок аргументов при этом привычный:
`gotoxy(x, y)` — первым идёт колонка. Рантайм сам меняет их местами:
`4.(R5)` = x (колонка) выводится вторым, `6.(R5)` = y (строка) — первым.

### Цвет текста — setTextColor(c)
```
ESC 0240 <цифра>
27, 160, color+48
```
0240 окт = 160 дес. Цвет — ASCII-цифра '0'..'7'.

**Таблица цветов (снято попиксельно со скриншота эмулятора):**

| Код | Цвет      | RGB на экране | Биты (б2=R б1=G б0=B) |
|-----|-----------|---------------|------------------------|
| 0   | чёрный    | 0,0,0         | 000                    |
| 1   | синий     | 0,0,255       | 001                    |
| 2   | зелёный   | 0,255,0       | 010                    |
| 3   | голубой   | 0,255,255     | 011 (зелёный+синий)    |
| 4   | красный   | 255,0,0       | 100                    |
| 5   | малиновый | 255,0,255     | 101 (красный+синий)    |
| 6   | жёлтый    | 255,255,0     | 110 (красный+зелёный)  |
| 7   | белый     | 255,255,255   | 111                    |

**Раскладка бит: бит0 = синий, бит1 = ЗЕЛЁНЫЙ, бит2 = КРАСНЫЙ.**
Раньше здесь было «бит1=красный, бит2=зелёный» — неверно, из-за этого
названия 2/4 и 3/5 менялись местами.

Примечание: это палитра ТЕКСТА (консоль). Цвета ГРАФИКИ (cls/point/line, 0..3)
зависят от выбранной аппаратной палитры и могут отличаться.

### Цвет знакоместа — setPlaceColor(c)
```
ESC 0241 <цифра>   ; 27, 161, color+48
```
Задаёт цвет знакоместа (индекс 0), то есть фон под символами. Действует на
то, что выводится ПОСЛЕ него: уже нарисованные участки экрана не
перекрашиваются. Так что фоновые «плитки» рисуются пробелами с нужным
setPlaceColor — на этом держится вывод кубиков в демо-тетрисе.

### Цвет фона
```
ESC 0242 <цифра>   ; 27, 162, color+48
```
В билтины не обёрнут — только вручную.

### Цвет курсора — setCursorColor(c)
```
ESC 0247 <цифра>   ; 27, 167, color+48
```
0247 окт = 167 дес. `setCursorColor(0)` гасит курсор на чёрном фоне.

### Режим экрана
```
ESC 0246 <цифра>   ; 27, 166, ...
'1' = 80 колонок, '2' = 40 колонок
```
В билтины не обёрнут — только вручную.

## Кириллица в строках

Русский текст в строковых литералах РАБОТАЕТ: `CodeGen.Koi8Uknc()` переводит
символ в код знакогенератора УКНЦ.

| Диапазон | Что                                                       |
|----------|-----------------------------------------------------------|
| 192..223 | строчные, в порядке `юабцдефгхийклмнопярстужвьызшэщчъ`     |
| 224..255 | заглавные, в порядке `ЮАБЦДЕФГХИЙКЛМНОПЯРСТУЖВЬЫЗШЭЩЧЪ`    |

То есть код = 192 + позиция в строке (для строчных), 224 + позиция (для заглавных).
Например `С` = 224+19 = 243, `А` = 225.

**Буквы `Ё`/`ё` в знакогенераторе НЕТ** — как и любого другого не-ASCII
символа вне таблиц выше: подставится `?` (63). Писать «зеленый», «желтый»,
«черный».

## Периферийный процессор: графика

Регистры на магистрали ПП (доступны коду, который выполняется НА ПП —
то есть резиденту, а не программе ЦП).

| Регистр  | Назначение                                              |
|----------|---------------------------------------------------------|
| 177010   | адрес в планах (видеоОЗУ), автоинкремента нет           |
| 177012   | данные плана 0                                          |
| 177014   | данные планов 1 и 2 (план1 младший байт, план2 старший) |
| 177016   | код цвета точки, 0..7                                   |
| 177024   | регистр октета точки, 0..377 (бит = точка, бит0 левая)  |
| 177020   | код цвета фона, точки 1-4 октета                        |
| 177022   | код цвета фона, точки 5-8 октета                        |
| 177026   | маска планов: в какие планы запретить запись            |

**`177024` — быстрый вывод октета.** Обращение БАЙТОМ (`MOVB`) рисует по
старому фону, обращение СЛОВОМ (`MOV`) — со стиранием. Это готовый механизм
для прозрачных и непрозрачных спрайтов без ручной сборки планов.

**`177020`/`177022` — цвет фона октета.** Вместе образуют одно целое: на
каждую из восьми точек по тетраде, в тетраде биты R, G, B (старший бит не
используется). `177020` описывает точки 1-4, `177022` — точки 5-8.
Пример: чтобы первая точка была чёрной, вторая голубой, третья зелёной и так
далее до белой восьмой, пишем в `177020` двоичное 0011 0010 0001 0000,
в `177022` — 0111 0110 0101 0100.

**`177026` — маска планов.** Запрещает запись в указанные планы. Со стороны
ЦП запись в зелёный и красный планы не блокирует.

Память ПП: ОЗУ 0-77777, ПЗУ 100000-177777 (32 КБ + 32 КБ).

## Аппаратная палитра

Четыре пары ячеек, каждая задаёт соответствие «цвет в плане → цвет на
экране». Смена мгновенная, поэтому годится для вспышек и затемнений без
перерисовки кадра.

| Ячейки      | Где меняются цвета         |
|-------------|----------------------------|
| 2400, 2402  | верхняя служебная строка   |
| 2470, 2472  | сам экран                  |
| 4700, 4702  | меню установок             |
| 6750, 6752  | нижняя служебная строка    |

Формат: в каждом слове четыре тетрады, побитно слева направо — яркость,
красный, зелёный, голубой.

```
АДРЕС   |0000|0000|0000|0000|     АДРЕС+2 |0000|0000|0000|0000|
         белый желт фиол красн            бирюз зел голуб чёрн
```

Обнуление обеих ячеек гасит экран целиком (все цвета становятся чёрными) —
удобно рисовать невидимо, а потом показать готовый кадр.

Оговорка из источника: на машинах завода «Квант» яркостный бит не работает
вовсе, на части машин СЭМЗ он инвертирован, а в поздних партиях выходы
красного и зелёного поменяны местами. То есть на яркость полагаться нельзя.

## Клавиатура (магистраль ПП)

| Регистр | Назначение                  |
|---------|-----------------------------|
| 177700  | регистр состояния, вектор 300 |
| 177702  | регистр данных              |

- разряд 6 состояния — разрешение прерывания с вектором 300;
- разряд 7 состояния — готовность: ставится при нажатии И при отжатии,
  **сбрасывается чтением регистра данных**;
- данные, разряды 0-6 — код нажатой клавиши; при отжатии значимы только

**Важно для режима Game.** Пока резидент занимает ПП, штатный обработчик
успевает прочитать `177702` первым и гасит готовность — свой опрос увидит
пустой регистр. Поэтому резидент при старте делает `BIC #100, @#177700`
(запрет прерывания), а при остановке возвращает `BIS #100, @#177700`.

## Загрузка программы в ПП

Массив параметров передаётся по каналу К2: данные в `176676`, готовность
проверяется по `176674` (`TSTB` / `BPL`). Формат массива:

```
MASSIV: .BYTE  0        ; код ошибки или 0
COMAND: .BYTE  0        ; 1 выделить, 2 освободить, 10 чтение, 20 запись, 30 пуск
TYPDEV: .WORD  32       ; устройство = периферийный процессор
ADR$PP: .WORD  0        ; адрес ОЗУ ПП
ADR$CP: .WORD  0        ; адрес ОЗУ ЦП
LENGTH: .WORD  0        ; длина программы В СЛОВАХ, не в байтах
ADRMAS: .WORD  MASSIV   ; всегда начальный адрес массива
        .WORD  401      ; стоповый элемент
```

Порядок: «выделить» (ПП возвращает адрес в `ADR$PP`), «запись», «пуск», а по
окончании «освободить». Программа для ПП должна заканчиваться `RTS PC` и быть
перемещаемой — адрес размещения заранее неизвестен. Если памяти не хватило,
`MASSIV` возвращается ненулевым, а в `LENGTH` — размер свободной памяти.

Так работает `pp_init()`: команды 1, 20, 30 через `PPSEN2`.

## Звук

| Регистр | Назначение                                        |
|---------|---------------------------------------------------|
| 177710  | состояние таймера; разряды 1-2 — период тактовой  |
| 177712  | буферный регистр, **12 разрядов**, не 16          |
| 177714  | регистр текущего значения                         |
| 177716  | разряды 7-12 управляют звуком                     |

Период тактовой частоты задают разряды 1 и 2 регистра `177710`:
00 — 2 мкс, 01 — 4 мкс, 10 — 8 мкс, 11 — 16 мкс.

Разряд 7 регистра `177716` включает звук, разряды 8-12 выбирают готовую
частоту (при 16 мкс: 60 Гц, 250 Гц, 500 Гц, 1 кГц, 8 кГц). Если разряды 8-12
нулевые, частота определяется тем, как быстро программа переключает разряд 7
— но тогда высота звука плавает от машины к машине.

Стабильный путь — прерывания программируемого таймера (вектор 304), период
кладётся в `177712`. Значение считается как A/F, где F — нужная частота, а
A зависит от периода: 62500 для 16 мкс, 125000 для 8 мкс, 250000 для 4 мкс,
500000 для 2 мкс. Длительность ноты удобно отмерять сетевым таймером
(вектор 100, 50 тиков = 1 секунда).

## Резидент ПП: что ломается чаще всего

Резидент — программа, которую ЦП загружает в ОЗУ ПП и запускает. Общается
с ней через ячейку команды и набор параметров в памяти ЦП, которые резидент
читает окном 177010/177014.

### Границы копируемого кода

Резидент копируется в ПП **целиком между метками начала и конца**. Любая
новая подпрограмма или ячейка данных, к которой он обращается, обязана
лежать внутри этих границ. Код, оказавшийся снаружи, в ПП не попадёт, а
переход на него уведёт в случайное место — экран замирает без всяких
сообщений.

### Чужие подпрограммы затирают регистры

Дважды подряд ловил один и тот же класс ошибки: значение держится в
регистре, а вызванная между делом подпрограмма его затирает.

| Подпрограмма | Портит |
|--------------|--------|
| отправка массива параметров в ПП | R2, R3 |
| запись октета под маской | R3, R5 |
| сдвиг строки, вывод строки | R0, R1, R5 |

Симптомы получаются обманчивые. Затёртый адрес источника при загрузке — и
в ПП уезжает мусор вместо спрайта. Затёртый счётчик строк — и спрайт
тянется вниз до бесконечности. Причём **быстрый путь может работать, а
буферный ломаться**: маски вызываются только при координате, не кратной
восьми, поэтому неподвижный фон рисуется правильно, а подвижный объект
разъезжается.

Правило простое: всё, что нужно после вызова чужой подпрограммы, держать в
ячейке памяти, а не в регистре.

### Регистр адреса один на всех

`177010` обслуживает и чтение памяти ЦП, и запись в видеопамять. Если
чередовать «прочитать слово данных — записать октет», на каждый октет
уходит по две переустановки адреса. Быстрее прочитать строку целиком в
буфер, а потом выложить её: адрес ставится дважды за строку, внутри
работает `INC @#177010`.

### Спрайты в ОЗУ ПП

Данные спрайта можно один раз загрузить в память ПП тем же протоколом
канала К2, которым грузится сам резидент: команда 1 выделяет память и
возвращает адрес, команда 20 переписывает туда данные. После этого резидент
читает спрайт напрямую, `MOV (R4)+`, без окна — четыре команды на октет
против двенадцати. Загружать нужно **до** запуска резидента.

Размеры спрайта после загрузки лучше передавать из ЦП, а не вычитывать
заголовок из ОЗУ ПП: при ошибке в адресе оттуда придут бессмысленные
ширина и высота, а это мусор на весь экран и зависший резидент. Проверка
размеров на входе стоит четыре команды и превращает зависание в «ничего не
нарисовалось».

## Соглашение о вызовах рантайм-подпрограмм

Пролог: `MOV R5,-(SP)` / `MOV SP,R5` / `MOV R0,-(SP)`.
После него первый аргумент = `4.(R5)`, второй = `6.(R5)`, третий = `10.(R5)`.
Аргументы кладёт вызывающая сторона, она же снимает их со стека
(`ADD #2., SP` на каждый).

## Чеклист при добавлении рантайм-функции с управляющими кодами

- [ ] Все `#N.` — десятичные, сверил по таблице ASCII
- [ ] ESC = `#27.` (НЕ `#33.`!)
- [ ] CR = `#13.`, LF = `#10.` (НЕ `#15.`/`#12.`!)
- [ ] Перевод строки = CR + LF, оба байта
- [ ] Вывод в порт через MOVB (порт 177566 нечётный)
- [ ] Перед MOVB — ожидание `TSTB @#177564 / BPL`
- [ ] Для gotoxy: строка выводится РАНЬШЕ колонки
- [ ] Цвет: бит0 синий, бит1 зелёный, бит2 красный
- [ ] Новый код резидента лежит ВНУТРИ копируемых границ
- [ ] После вызова чужой подпрограммы не рассчитываю на R0-R5
- [ ] Метки добавлены в проверку коллизий, если нужно
- [ ] Аргументы со стека: первый = `4.(R5)`, второй = `6.(R5)`
